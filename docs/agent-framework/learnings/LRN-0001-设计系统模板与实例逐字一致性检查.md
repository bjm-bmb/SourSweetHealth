## 观察

项目把 `docs/android/design-system/*.kt.template` 作为通用组件的唯一来源，app 侧复制并替换包名后实例化。模板目录声明「可直接编译」，但实例化后如果只改 app 侧（补参数、修 API、加省略/间距），模板不会自动同步，容易出现「模板与实例漂移」。本轮实际发现 3 个模板与实例不一致：列表项缺少省略与尾部间距、输入框缺少 readOnly/enabled/visualTransformation/keyboardOptions/trailingIcon、进度条仍使用旧的 progress 签名；另有一个模板在页面标题字级调整后未同步。

## 证据

APP-001 的两次独立评审均执行了模板—实例比对：把模板中的 `{{package}}` 替换为 app 实际包名、统一换行后逐字比较，初次发现 3/10 不一致；修复后 10/10 逐字一致，`app_check` 0 ERROR，构建与单测通过。比对方法可复现：读取模板文本 → 替换包名 → 与实例文本做去换行差异比较。

## 建议沉淀

在 `tools/app_check.py` 增加确定性检查：当项目同时存在 `docs/android/design-system/<Name>.kt.template` 与 `app/src/main/java/<namespace>/ui/components/<Name>.kt` 时，替换 `{{package}}` 后逐字比较（忽略换行差异），不一致输出 WARN/ERROR 并列出差异文件；同步在 `tools/tests/` 增加「一致 / 漂移」两类夹具用例。`bjm-app-ui` 的收口步骤加入「模板—实例一致性」检查，`review-checklist.md` 增加对应条目，避免只靠人工记忆。
