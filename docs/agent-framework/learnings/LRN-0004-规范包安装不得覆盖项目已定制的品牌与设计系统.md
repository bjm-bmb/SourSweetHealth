## 观察

规范包安装脚本原本对 `docs/android/`（含 `design-system/`）与 `docs/brand/` 做整目录覆盖复制。但这两个目录在项目侧是**项目所有**：品牌技能会把 `brand-vi.md` / `brand-tokens` 重写为具体品牌，UI 技能会把设计系统模板实例化到 app 并可能补充项目组件。再次执行安装同步规范时，整目录覆盖会把这些项目定制内容全部还原成规范包的通用占位版，造成品牌与设计系统成果丢失。

## 证据

APP-001 交付后，项目侧的 `docs/brand/brand-vi.md`、`brand-tokens.kt.template` 与 `docs/android/design-system/`（含新增的聊天组件）均已定制；检查 `install/install.ps1` 发现 `Copy-TreeContent docs\android` 与 `docs\brand` 是无条件覆盖。若按流程提示重跑安装，会覆盖本轮成果。修复为 seed-if-absent（只补缺失文件）并新增 `-ForceBrandDocs` / `-ForceDesignSystem` 显式覆盖开关后，在目标项目上实际执行安装，品牌文件与设计系统组件哈希保持不变，安装退出码 0。

## 建议沉淀

`install/install.ps1` 对 `docs/brand/` 与 `docs/android/design-system/` 采用 seed-if-absent，保留已有项目文件并统计保留数量；提供 `-ForceBrandDocs` / `-ForceDesignSystem` 供显式覆盖；帮助文本与 README 的「更新机制」同步说明。安装脚本的回归验证应包含：在含定制品牌/组件的项目上重跑安装后，这些文件的哈希不变。
