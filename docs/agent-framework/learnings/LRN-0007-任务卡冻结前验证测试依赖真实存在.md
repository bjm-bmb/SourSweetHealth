## 观察

任务卡在受理阶段声称某测试依赖“为既有依赖”，但基线构建文件实际没有 `testImplementation`；任务卡又禁止修改构建文件，导致开发无法编译新增单测，只能返回 `BLOCKED`。

## 证据

APP-001 受理时写入“JUnit 4.13.2 为既有依赖”。开发阶段执行 `.\gradlew.bat :app:dependencies --configuration debugUnitTestCompileClasspath`，输出中不存在 junit 条目；任务卡禁止修改 `build.gradle.kts`，触发阻塞。后经需求方确认，修订任务卡允许新增一行测试依赖后解除。

## 建议沉淀

在 `bjm-app-intake`（任务卡起草）和 `bjm-app-delivery`（规划前检查）增加“测试依赖存在性”检查：当验收要求运行单测时，先执行 `.\gradlew.bat :app:dependencies --configuration debugUnitTestCompileClasspath` 或检查构建文件的 `testImplementation`；若缺失，必须在任务卡「依赖变更」中写明新增测试依赖及允许修改构建文件的范围。同步更新 `docs/agent-framework/task-template.md` 的填写提示，并在 `review-checklist.md` 增加对应核对项。
