## 观察

把既有界面迁移到设计系统时，`AppTextField` 只暴露 value / onValueChange / label / placeholder / singleLine。真实表单还需要：trailingIcon（日期/清空等尾部按钮）、keyboardOptions（数字、ASCII 键盘）、isError（校验错误态）、readOnly + menuAnchor（下拉只读框）、visualTransformation（口令遮蔽）、supportingText（辅助说明）。能力不足时界面只能退回原始 `OutlinedTextField`，导致「界面一律使用 App* 组件」的约束失效。

## 证据

某 Compose 项目全量规范化改造中，表单页与设置页共 7 个输入框因缺少上述参数退回原始组件；构建通过，但设计系统未能覆盖全部输入场景。

## 建议沉淀

扩展 `docs/android/design-system/AppTextField.kt.template` 的可选参数（trailingIcon / keyboardOptions / isError / readOnly / visualTransformation / supportingText），默认值保持向后兼容；同步 `docs/android/design-system/README.md` 的组件说明，实例化时仍逐字复制。
